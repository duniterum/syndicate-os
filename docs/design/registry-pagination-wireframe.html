What this wireframe binds

  • One new element only: the pager row under the table — range line left (mono, 12px, uppercase), Previous · page indicator (« 14 / 14 ») · Next right (44px touch targets). Nothing else on the page moves; the header above keeps its « Verified on-chain » pill exactly as deployed.
  • The register OPENS on page 1 (seats #1–#25 — a register reads from its beginning, and the admin pager's own default is page 1). Frame 1 shows the LAST page only because that is where the chapter boundary lives.
  • 25 seats per page — ONE shared constant. The pager renders ONLY when the register holds more than 25 rows — today's page (16) is byte-identical to prod. At build, the page size is the SAME imported constant the /admin/members pager uses, never a re-typed number.
  • Where this deliberately differs from the admin pager, it says so: the admin always shows its « Seats X–Y of N » line even on one page; here the WHOLE pager row (range included) stays absent at ≤25 rows — the public page stays pristine. The admin's page indicator is adopted; treatments snap to the site's named mono classes at build.
  • The range line counts register rows (list positions); with a contiguous seat set — as today — they coincide with the seat ordinals shown in the column.
  • Full-screen law holds: the table keeps filling the width; no page cap. Mobile keeps the sideways-scrolling 5-column table exactly as today.
  • Client-side paging over the payload the API already serves whole — no API change, no new endpoint, nothing for Replit.
  • Built on the site's Button atom: focus-visible ring and true disabled semantics inherited; visible « Previous »/« Next » labels need no extra ARIA.
  • Type treatments bind: serif display · Work Sans body · mono = data only · 12px floor everywhere. Both themes verified at the preview gate before any deploy.
  • The boundary row (#333 → #334, gold dashed rule in Frame 1) is illustrative of the chapter transition the server now resolves — sealed in 4b96b30, and the hero/header chapter badge now follows the same table (68ea337).
