## The record

A protocol that replaces its own sale engine has to answer one question before it can deploy: who is already a member?
Until 2026-06-21 that answer was spread across three sale contracts — the original engine, its replacement, and the replacement's own successor — each holding its own purchase events. On that morning the protocol stopped treating membership as a moving total and pinned it to a height: Avalanche C-Chain block 88,496,414, timestamped 09:47:32 UTC. Everything up to that block counted. Nothing after it did.
Read at that height, the three contracts resolved to eight distinct wallets — two first seen on the original engine, three on its replacement, three on the successor. Their order was not chosen: first block, then position inside the block, with the transaction hash as the final tie-breaker, numbered one to eight in that sequence. The eight were compressed into a single value, 0x6d81a73621dc9e4fd328b56aef67f98a8e4dde8e2adb68d85b9b87b8685f3329, and the artifact recording all of it was committed to the public repository four minutes after it was generated.
Three hours and four minutes after the freeze block, at 12:51:48 UTC, the third-generation sale engine was deployed with that value written into it.

## What the protocol did

It published the derivation, not the result.
The committed artifact carries the exact command that produced it, the height and the chain it was taken on, the ordering rule in words, the formula for each entry, the shape of the tree, and a proof for every one of the eight seats. The program that generated it is committed beside it, so the value can be rebuilt from the same inputs by anyone who does not believe the file.
It also made the artifact refuse itself. The generator writes nothing unless its own falsification tests pass first: a substituted wallet must fail to prove, an altered seat number must fail to prove, a wrong root must fail to prove, and a duplicate wallet or a repeated seat number stops the run with an error rather than being quietly absorbed. A test committed in the same act replays all eight proofs against the engine's real claim path and asserts the same refusals against the contract itself.
Then the protocol gave up the ability to change its mind. The value was not stored in a settable field; it was written into the deployed code at construction, where no owner key reaches it. The Founder cannot add a ninth historical member, cannot remove one, and cannot reorder them. The same deployment fixed where new numbering begins — the engine's own counter opens at eight, so the first seat sold on it was #9.

## Why this is recorded

Every protocol that changes engines meets the same temptation: carry the old members across in a private list, and ask everyone to accept it.
This one refused the list. It named a public block, published what it read there, published the rule it read by, published the program, published the tests that try to break it, and put the result somewhere it could never quietly edit. From that moment the protocol's own history stopped being something it asserts and became something a stranger recomputes — and the recomputation is built to disagree if the record is wrong.
It is also the exact place where the protocol gave up an option. A freeze is a boundary, and a boundary has a wrong side: a wallet whose first purchase landed after 09:47:32 UTC would have had to buy a new seat rather than carry an old one. As it happened, nobody did — the two later engines the freeze scanned have issued no seat since, their live counters still reading five and eight against opening offsets of two and five, the same three and three the freeze recorded. But the protocol did not know that when it chose the height. It chose a block it could not take back, published the consequence, and left both the number and the boundary on the chain to be checked.
