## The record

On 2026-06-27, at 08:24:13 UTC, a prototype workspace was imported into the protocol's public repository as an explicitly isolated, non-production area. It arrived carrying its own rules, written into the same import: the roles inside it were simulated flags stored in the visitor's own browser, labelled in writing as gating for the interface only and not security, with a standing instruction not to treat a stored founder mode as security, and a matrix stating that operator surfaces are hidden from non-operators rather than merely blocked.
Six hours, thirty-five minutes and sixteen seconds later, a review of that workspace found that its code did not obey the rules it had shipped with. The prototype's public tools page decided which groups of tools to display by asking the browser's founder flag alone. That flag is stored in the browser and persists on its own, independently of whether a wallet is connected — so a visitor who had at some point switched the prototype's own founder mode on, and was no longer connected, was still shown the operator group on a page written for everyone. The group held two entries: the founder console, and the screen for reviewing proposed burns.
The reach of this is not rounded up. In that prototype a browser starts disconnected, seated and not a founder, and the founder flag is set only by the prototype's own demonstration switch. The fault did not put those tools in front of an arbitrary visitor; it put them in front of any browser that had ever used that switch, on a surface that was supposed to answer the same way for everyone.

## What the protocol did

The correction, at 14:59:29 UTC the same day, did not add the missing connection test. It removed the question. The public tools page now drops the operator group unconditionally, whatever any flag in any browser says, and the full role logic survives only in the console that sits behind the connection gate, where an operator is genuinely connected. One line of code changed.
The same commit wrote the audit down and left it in the public repository: a hundred and twenty-five lines recording what was inspected, what was changed, and what was deliberately not changed — one fix, eight findings examined and cleared with no change, two problems deferred with their reasons, four items marked as requiring real wiring and therefore out of scope, and no decision needing the Founder. The document states its own limits in its opening paragraph: the pass covered that one workspace, touched no production code and no real wiring, and was a cleanup rather than a feature sprint.

## Why this is recorded

The rule was already written, in the same import, hours before anyone read the code against it: do not treat a stored founder mode as security. The code departed from it anyway. That is the whole of it — a rule written down does not enforce itself, and nothing but reading the code against the rule found the gap.
It is recorded with its limits attached, because the limits are part of the truth. By its own charter the workspace was not the live site: that charter names the production application as the real live site and forbids copying prototype files into it as production truth. Nothing in the record establishes whether this prototype was ever served to anyone, and this register does not claim that it was not. What is recorded is a defect that stood in a public repository between one commit and the next, the audit that found it, and the correction — all three still readable, at their original timestamps, by anyone who wants to check.
