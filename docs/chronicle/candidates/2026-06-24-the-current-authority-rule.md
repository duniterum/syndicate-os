## The record

A protocol built across many sessions accumulates documents that describe it. On 2026-06-24 the protocol wrote down what those documents are worth at the moment a transaction is signed, and filed the finding as critical.
The situation was ordinary. A set of arguments for a transaction had been prepared, reviewed and frozen in a packet — an internal test source record for the on-chain source registry. Between the freeze and the signature, everything a frozen packet cannot see may have moved: who owns the target contract, whether an ownership transfer is pending, whether the selected signer is still that owner, whether the record already exists, what the sale contract points at, what the public site is serving.
The operational ledger states the cause without softening it — lineage and readback logs explain how the protocol arrived at a state, but they do not prove that state is still current at the moment of execution — and states the rule in one line: “Current authority always beats remembered authority. Lineage explains how we arrived here. Readbacks prove where we are now. Execution must use current truth: never remembered truth, never historical truth alone, never stale documentation alone.”
The same discipline was written into the contract ledger the same day, as a separate entry with its own title, “Current readback is execution authority”, and its own wording. Two related entries, dated 2026-06-24 — not one text copied twice.
That morning, at 09:11:50 UTC, the packet's transaction was signed and the source record was created on the registry. It succeeded, and the record was created paused.

## What was decided

The rule was turned into a procedure. A Current Authority Check now stands at the head of the source-creation runbook and the activation runbook, to be run immediately before the Founder signs: confirm the chain, confirm bytecode exists at the target address, read the owner and the pending owner, confirm the selected signer equals that current owner, confirm the source id does not already exist and is not active, confirm the sale still points at this registry, confirm public purchases still carry the empty source id. Stop if any value differs from the packet — update the packet first, then run the check again.
It was also made a build failure. One commit, “Harden ceremony authority memory”, changed nine files: eight documents and one test. The test additions — twenty-eight assertions, one for each phrase that must not disappear — cover all eight of those documents. A later session that quietly dropped the rule from any of them would break the build rather than the ceremony.
On the order of the day, this record claims only the date. The chain fixes the transaction at 09:11:50 UTC. The commit that wrote the rule into those nine files carries an author time of 09:31:25 UTC — nineteen minutes and thirty-five seconds later. Both ledger entries say of themselves that they were added before the source-record ceremony; the repository's own clock says the writing was committed after the transaction. A commit timestamp is written by the same machine as the document, so it is the repository describing itself, exactly as the note does. Only the transaction's minute comes from outside the repository. Which came first is not established here, and this entry does not assert it.

## Why this is recorded

It is recorded for two reasons. The first is the failure it names, which is this protocol's most likely one. It is built across many sessions and more than one machine, and each of them carries a version of the truth that was current when it last looked. A frozen packet, an earlier readback, a confident sentence in a chat window — each of them describes a state that was. The decision written down that day was not to remember better. It was to stop treating memory as authority at the moment of signature, and to rebuild the state from the chain immediately before every signed act.
The second is what the rule is attached to. The record created that morning was created paused, and a paused record is inert: the sale contract asks the registry for attribution terms and requires the record to be active, so while it stayed paused it could attribute nothing and pay nothing. There is no loss here and no wreckage to point at. A protocol that writes down only the lessons that cost it money is keeping a damage log, not a memory; this rule was written on the day of an act that moved nothing, and then pinned by a test so that no later session could drop it quietly.
